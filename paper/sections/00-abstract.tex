\begin{abstract}
AI agents turn model decisions into processes, subprocesses, and network connections. To account traffic per task and to scope egress policies, network and service management must know which agent execution opened each connection; the kernel, however, sees connections, not executions. Existing eBPF-based agent systems rely on process lineage, cgroups, inherited task identifiers, or application bindings; each signal is valid only for specific execution structures, and none of the systems we inspected fully provides both explicit ambiguity and validation against an independent reference. We present agentnet, which fuses lineage, cgroup membership, and a runtime-provided execution identity and reports ambiguity explicitly. It binds the identity to the asynchronous task rather than the thread, so it remains correct for asynchronous tools in a shared Model Context Protocol (MCP) server, and uses it for both live per-execution accounting and an in-kernel egress policy. We evaluate agentnet on IPv4 TCP connection attempts against a destination-based reference that shares no input with the system. When executions have distinct process trees, fusion turns every faulty label into reported ambiguity. In a shared MCP server, the task-scoped binding removes the misattributions that thread-keyed markers cause for asynchronous tools, emulations of the time-window and latest-binding correlation of related systems misattribute up to 99\% of the connections of concurrent tools, and the egress policy makes no decision error; with four concurrent LLM agents, attribution and policy decisions match the reference. The optimized collector adds 8.1\,$\mu$s (without markers) to 14.3\,$\mu$s (with markers) to the median loopback \texttt{connect} latency.
\end{abstract}
