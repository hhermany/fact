\begin{abstract}
Artificial intelligence (AI) agents turn model decisions into processes and network connections, often many at a time on a shared host. Network management must then answer: which agent execution opened this connection? Without the answer, per-execution accounting and egress policies fail silently: traffic is credited to the wrong execution, and a forbidden connection can pass under another execution's permissions. Existing agent systems based on the extended Berkeley Packet Filter (eBPF) infer the execution from signals that hold only for some execution structures. We present \solution{} (Fused Attribution, Accounting, and Control per Task), which binds each tool call's identity to the asynchronous task that runs it, hands it to the kernel when a connection or process is created, combines it with process lineage and control groups (cgroups), and reports ambiguity instead of guessing; the same identity drives live accounting and an in-kernel egress policy. Evaluated on TCP connection attempts against an independent reference, \solution~attributes every connection correctly in a shared Model Context Protocol (MCP) server with concurrent asynchronous tools, over loopback and a real network interface, and with up to eight agents driven by open models and by commercial models from Anthropic and OpenAI; AgentProvenance, run on the same MCP workload, misattributes up to 96\%. Faulty labels stay confined to the faulty calls, and, where executions have their own process trees, an in-kernel lineage check blocks every bypass they would cause. The collector adds 8.1 to 14.3\,$\mu$s to the median loopback \texttt{connect} latency.
\end{abstract}
